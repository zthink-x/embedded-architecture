# 每次改码后的资源占用报告

这是每次完成一组固件代码修改后的固定交付项，不要求每次按键编辑都重新测量。适用于功能修改、重构、配置变更和优化；纯 skill 文档编辑不产生目标固件运行占用。报告当前值、容量/预算、余量、占用率及与可比基线的变化，并标明数据来源。

## 统一显示单位

- RAM、ROM/Flash、栈、堆及其他存储/缓冲容量统一用 **KB** 报告，已用量、容量、余量和修改前后增减量均遵循此规则；本报告约定 **1 KB = 1024 字节**（二进制换算，等同 KiB），不使用表示位的 kb。
- 工具原始结果可保留字节数供核验，面向用户的汇总表统一换算为 KB；栈统计若以 word 为单位，先按该平台/API 的实际 word 大小换算为字节，再换算为 KB。
- 默认保留两位小数；很小的非零占用或变化增加小数位或标为小于显示精度，不能四舍五入后误报为零变化。先用原始精度计算差值和占用率，再格式化。
- CPU 占用和存储占用率使用百分比，CPU 前后变化使用百分点；时间和频率仍使用各自适当单位。

## 采集顺序与证据

1. 改码前尽可能保留当前目标配置的构建产物、map/size 输出与现有运行测量。记录源码版本或差异标识、固件标识、板型、工具链、优化级别、LTO/调试配置和链接布局。
2. 修改后构建同一目标配置，提取新 ELF/map 或工具链等价报告。不得用旧产物说明当前源码；构建失败时旧数据只可列作历史基线。
3. 有板卡和可用测量通路时，在记录好的代表性负载下测 CPU、栈和堆；优先复用已有统计，缺失时按需增加低开销观测。不为得到数字擅自触发未授权的电机动作或硬件操作。
4. 对当前值与基线作同口径比较。没有基线写“无基线”；配置、工作负载或计时方法不同写“不可直接比较”，不计算误导性差值。
5. 每次代码交付附下述表格和证据位置。缺少工具链、硬件、运行日志或容量定义时，仍报告已知项，并逐项说明缺测原因及如何补测。

如果只是注释变化，仍确认当前构建对应修改后的源码。只有已证明运行镜像与运行配置不变时，才可引用同一镜像的历史实测，并标明测量时间和复用理由；否则 CPU 旧值只能作为历史参考。

## Flash/ROM 与 RAM 的统计口径

- Flash/ROM 依据链接结果的实际存储区域和加载地址统计代码、只读数据、向量表、初始化数据镜像及其他需烧录内容；不要将 ELF 文件大小、调试信息或 `size` 的总计直接当作 Flash 占用。
- RAM 按运行地址统计静态数据、零初始化区和自定义段，覆盖 `.data`、`.bss`、`.noinit`、DMA 缓冲等实际存在的分区。Flash 中的初始化镜像和 RAM 中的运行副本分别消耗各自资源。
- 可用容量以本固件链接区域/分区为准，说明 Bootloader、持久化区域及其他预留的扣除；不能直接拿芯片总容量作应用可用容量。
- 有多块 RAM/Flash 时分别列出，例如目标实际存在的 DTCM、SRAM、IRAM/DRAM、PSRAM 和应用 Flash 分区；不假定所有 MCU 均有这些区域。分别报告各区域的占用与余量，避免总和掩盖单区溢出。
- 区分有效段字节数、对齐/空洞造成的区域占用及已预留空间。统一明确百分比的分子与分母，不混用段大小和地址跨度。
- 分别报告“链接期静态占用/预留”和“运行期堆栈使用”。静态分配的 RTOS 堆池、任务栈或帧缓冲可能已在 `.bss` 中，不得再次加到 RAM 总量；从堆分配的任务栈同样避免与堆使用量重复累计。
- 使用当前目标工具链的 `size -A <当前ELF>`、map 和段/程序头信息交叉检查；`arm-none-eabi-size` 仅适用于相应 Arm 工具链，Xtensa/RISC-V 或其他目标使用工程实际工具。ESP-IDF 项目可结合当前版本的 `idf.py size` 等报告；不能使用宿主工具的结果替代未经核对的目标统计。简化的 `text + data` / `data + bss` 仅在链接布局支持该口径时作参考，不能漏掉自定义段。

## CPU 占用的测量口径

- CPU 占用必须基于运行时间数据；不能由代码行数、Flash 大小或是否使用 DMA 推算。预算估算必须单列为估算，不放进“当前实测”列。
- 裸机可累计有界工作区间与 ISR 的时间，或使用经过核对的空闲时间统计。RTOS 可使用运行时间统计/跟踪，明确中断时间是否被计入被打断任务或 idle，不能未经核对就把任务百分比之和当作总 CPU 占用。
- 使用忙碌时间法时，`占用率 = 不重叠的忙碌时间 / 同一观察窗口时长 × 100%`。使用空闲时间法时，须说明何为 idle、ISR 如何归属及睡眠时间如何计入，才能报告 `1 - 空闲占比`。
- 若只能测到某个控制函数，标为“该函数 CPU 时间贡献/耗时”，不能当作整机 CPU 占用。忙等即使没有有效计算也占用 CPU，不能将它误计为空闲。
- 明确计时源、频率、回绕处理与分辨率；按目标选择 SDK 运行统计、硬件定时器或周期计数器，DWT 不是跨 MCU 通用能力；核对睡眠与变频行为。包含中断的函数墙钟耗时与独立 ISR 计时不得重复相加。
- 报告指定场景下的窗口平均占用、固定采样窗口的最大观察占用、窗口长度和测量时长。启动阶段与稳态、正常负载与高负载分别标识；最大观察值不等于理论最坏值。
- 有多核时按核报告并说明汇总口径。统计/日志本身的开销也要说明；不以一次空载运行代表实际工作负载。

## 栈、堆与相关运行资源

- 栈：报告主/中断栈及相关 RTOS 任务栈的配置容量、最小观测余量或最大观测使用；注明工具/API 的字节或字单位。填充扫描或高水位法有方法限制，不保证覆盖全部路径。
- 堆：报告分配器可用容量、当前使用/空闲、历史最大使用或最小空闲；有能力时补充最大连续空闲块和分配失败次数。标明分配器管理开销是否包含。
- 工程确认未使用堆时写“不适用：无堆分配”；未开启统计则写“未测”，不能写“0”。仅有栈/堆配置大小时标为预留容量，不宣称是运行使用量。
- 与本次改动有关时补充队列高水位、DMA/帧缓冲大小、控制周期耗时和超期次数；它们不能替代 CPU/RAM/Flash 核心项目。

## 交付表格

下表是填写结构，不能把占位说明当作测量值。多 RAM 区域、多任务栈按实际情况拆行；未知容量时可报告绝对值，但占用率/余量标为未知。

| 项目 | 当前值 | 容量/预算与余量 | 较修改前变化 | 来源与条件 |
| --- | --- | --- | --- | --- |
| CPU 平均占用 | 实测百分比或未测 | 可用预算/测量口径 | 百分点差或不可比 | 场景、时长、窗口、计时源、固件标识 |
| CPU 最大窗口占用 | 实测百分比或未测 | 窗口长度/预算 | 百分点差或不可比 | 同上；不是瞬时峰值或理论上界 |
| Flash/ROM 各区域 | KB、占用率 | 应用区域容量、余量（KB） | KB 差值或无基线 | 当前链接报告/产物 |
| RAM 各区域静态占用及预留 | KB、占用率 | 区域容量、未占用空间（KB） | KB 差值或无基线 | 当前 map，说明包含的堆栈预留 |
| 栈（按栈/任务） | 最大观测使用或最小观测余量（KB） | 配置容量（KB） | KB 差值或未测 | 运行高水位/跟踪，单位与场景 |
| 堆 | 当前和最大观测使用/最小空闲（KB） | 分配器容量、剩余（KB） | KB 差值或未测 | 分配器统计，是否计入管理开销 |

报告中附上实际构建命令/日志、map/ELF 路径或相应可访问结果，以及运行测量的固件标识和条件。资源回归时解释主要增量来源；只有存在项目明确预算时才判定超限，不擅自设定统一的“80%危险线”。无法实测的项目说明最小补测步骤，不隐瞒、不填估计数字冒充测量。

工具依据：[GNU size](https://sourceware.org/binutils/docs/binutils/size.html) 用于确认段统计格式；[FreeRTOS 运行时间统计与调试](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/main/ch12.md) 用于理解任务统计机制。实际命令/API 与计时配置以工程版本为准。
